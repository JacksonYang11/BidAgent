# 在线智能招投标Agent

WhaleTalk 的本地人力资源招投标演示工作台。FastAPI 提供网页和接口，浏览器使用本地 PDF.js；文件识别、任务及 Word 导出在本机运行，分析与生成真实调用 DeepSeek 官方 API。

## 当前能力

- 文字型、扫描型和混合型 PDF 上传、预览、文字提取及中文 OCR。
- 指标需求、评分要求、废标红线三类分析；原文摘录校验、页码跳转及位置高亮。
- 人工编辑分析结果、企业资料维护、投标目录及章节生成。
- 章节编辑、单章重写、版本恢复、需求响应清单和 Word 导出。
- 历史任务、本地持久化、任务取消、失败重试与提取/分析/生成检查点。
- 服务端 Key、同源本地会话、CSRF、文件隔离、有限调用预算、Git 候选文件秘密扫描。

未配置 Key 时允许上传、PDF/OCR 提取、原文预览及本地资料编辑；AI 按钮明确不可用。应用不存在模拟分析开关。测试里的模型替身仅用于验证处理流程，不能代替真实 API 验收。

## 环境

已在 macOS Apple Silicon、Python 3.12、Node.js 环境验证。建议 Python 3.12、Node.js 20 或更新版本。Node 只用于安装本地浏览器资源，正常运行不需要前端开发服务器。

首次安装需要联网下载 Python 依赖和前端库。RapidOCR 包含识别模型，启动时不临时下载模型。OCR 在 CPU 上运行。

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
npm ci --ignore-scripts
npm run assets
.venv/bin/python scripts/init_config.py
```

其他平台需要重新验证本地 OCR、原生库和浏览器；不要假设 macOS 的完整依赖锁定在所有架构上均可用。

## 配置 DeepSeek

在本机 `.env` 中填写 `DEEPSEEK_API_KEY`。不要在聊天、截图、源码、命令行参数或提交中包含实际 Key。默认模型 ID 为 `deepseek-v4-flash`，通过 `DEEPSEEK_MODEL` 可调整；需要确认该模型在实际账号中可用。

接口仅接受 `https://api.deepseek.com` 或其 `/v1` 路径。默认不继承 HTTP 代理、不跟随重定向、保留 TLS 校验。Key 仅在后端请求头中发送。

`.env` 文件权限为 0600，数据目录权限为 0700。环境变量优先于 `.env`；配置变化后重启服务。`.env` 是本机明文文件，不是加密保险库。

## 启动

```bash
.venv/bin/python run.py
```

浏览器访问 [本地工作台](http://127.0.0.1:8000)。也可双击项目中的 `start.command` 启动。端口占用时，在 `.env` 修改 `APP_PORT`，访问对应的新地址。不能使用 `localhost` 别名或局域网地址绕过 Host 校验。

默认仅监听 `127.0.0.1`，不要改成公网或局域网服务。本 Demo 不包含多用户认证、HTTPS 部署或生产级权限管理。

## 使用顺序

1. 在“企业资料”中录入已确认的企业事实，可暂时留空；示例资料勾选虚构标记。
2. 新建任务并上传 PDF，等待提取完成。必要时打开“提取文本”核查 OCR。
3. 点击“AI 解析”，确认相关文本发送至 DeepSeek。检查三个标签页和来源证据。
4. 修改分析条目后保存，再生成投标初稿。缺失资质、案例、报价和人员信息用占位符表示。
5. 核对章节、响应覆盖和警告，编辑或重写章节，导出 Word。

默认单文件 50 MB、150 页，一次执行一个重任务。页面进度来自实际阶段；模型请求中无法准确预估剩余时间。

DeepSeek 请求显式关闭思考模式，避免思考占满额度而没有生成 JSON。默认每批约 8,000 字符、单次输出上限 16,384 tokens、请求超时 300 秒；输出配置允许 500 至 65,536，片段配置允许 1,000 至 100,000 字符。这些是本 Demo 的保护线，不是官方模型的能力上限。

默认每个任务最多 200 次模型请求、总用量保护线 2,000,000。发送前按输入字符数加最大输出额度保守预留，收到有效 usage 后按实际 total_tokens 结算；超时或缺失 usage 时保留预留额。该保护线不是人民币金额，也不是精确费用承诺。实际 usage 与结束原因单独保存在本地，不记录模型思考原文。

分析结果被截断时，自动拆小失败片段，最多递归 4 层；超长单块也会按原文分段，保留原块引用和边界重叠。成功片段和拆分路径会保存，重试时复用；失败片段不会被计为成功。目录及章节截断时可在最多 3 次尝试内逐步增加输出额度，最高 65,536。所有请求仍受任务调用次数及总预算限制。达到保护线后停止并保留检查点，可调整本机预算后手动重试。取消本地任务不能撤销已经发出的付费请求。

## 测试

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/security_check.py
npm audit --omit=dev
```

浏览器测试使用 Playwright 和独立 Chrome。可在本机安装 Playwright，或通过 `PLAYWRIGHT_MODULE` 指向已有安装。`tests/browser.mjs` 针对未配置 Key 的真实本地应用，执行上传、预览、翻页、资料保存及响应式检查，会创建明确的测试资料。

完整 UI 流程使用隔离测试服务：

```bash
# 终端一：仅用于测试，不是对客户展示的服务
.venv/bin/python -m tests.serve_fixture
# 终端二
node tests/browser_flow.mjs
```

隔离服务使用 8001 端口及 `tmp/browser-fixture/`，由测试代码注入模型替身；应用正常启动入口 `run.py` 永远使用官方模型客户端。截图和测试导出物保存在 `tmp/browser/`，均被 Git 忽略。

## GitHub 上传前

1. 保持 `.gitignore`：秘密配置、上传文档、数据库、OCR 中间文件、参考材料、导出物、日志、虚拟环境及测试截图不入库。
2. 运行 `scripts/security_check.py`。它检查 Git 跟踪和未忽略候选文件、暂存内容、凭据模式及本机配置秘密的精确匹配；不会输出秘密值或上传扫描内容。
3. 查看 `git status --short` 和暂存变更，确认只包含计划发布的源码、文档、锁定文件和 Logo。
4. 提交后再做依赖漏洞检查；扫描不是无漏洞保证。若曾泄露 Key，撤销并轮换，不能只删除文件。

## 实现选择与限制

- UI 采用 Nexus-B 的颜色、侧栏、按钮、表格及工作台结构；项目名称和品牌采用 WhaleTalk。
- OCR 使用 RapidOCR / ONNX 的本地中文模型，替代方案中的 PaddleOCR Python 运行时，以减少当前 Apple Silicon 环境依赖。两者不是同一个软件包；实际扫描和混合页已单独测试。
- 以 PDF 可见页面为证据；无法恢复截图裁切或未显示的滚动内容。OCR 和跨页表格仍需人工核对。
- 引用“已验证”仅表示摘录匹配提取文本；OCR 引用始终保留待核对标记。不能据此宣称业务判断无误或企业资格已验证。
- 生成完成会标记依据中未匹配的数量、金额或承诺。响应覆盖清单表示章节关联，不代表评分必得或全部合规。
- 使用截图区域与文字块分段，保留相邻块上下文；不做通用复杂排版的无损恢复。
- 已完成有效 Key 的连通性验证，以及用户手动上传文件两个片段的真实 DeepSeek 分析回归。全篇分析、生成质量及目标人力资源业务效果仍需手动验收；局部回归不代表整份文件已完成分析。

产品方案与技术方案随仓库发布在 `docs/` 目录；本机验收记录仍保留在开发电脑，不随 GitHub 仓库发布。业务样本、PDF、Word、演示文稿及 Excel 文件默认不入库；新增参考资料请放在被忽略的 `references/` 目录。README 与第三方许可说明保留在仓库中。

当前演示电脑为避免已有服务端口冲突，在本机 `.env` 使用 `APP_PORT=8002`；访问 [当前 Demo](http://127.0.0.1:8002)。默认配置示例仍为 8000。
