# 人力资源招投标 Agent Demo 产品方案

版本：v1.0  
日期：2026-09-07  
状态：初步洽谈演示版开发依据  
配套文档：[技术方案](./技术方案.md)

## 1. 项目目标

为 FDE 团队与人力资源服务公司的初步洽谈准备一个可本地运行的网页 Demo。通过客户提供的真实招标 PDF，演示从理解采购要求、整理评分与风险，到生成精简投标初稿的完整流程。

核心价值是缩短阅读招标文件、整理响应要点和起草方案的时间。Demo 必须真实调用 DeepSeek，不能以预置答案或模拟进度代替分析。已完成任务可以保存并再次展示，但必须明确它是历史结果。

本地运行指网页、文件处理、存储和导出在演示电脑上运行。AI 分析仍需联网，相关招标文本及生成所需的企业资料将发送至 DeepSeek。

## 2. 用户与演示场景

- 主要用户：人力资源公司投标负责人、方案编写人员、业务负责人。
- 演示人员：FDE 团队，可预先配置 API Key 和示例企业资料。
- 典型场景：上传人力资源服务招标文件，查看关键要求及证据，生成方案并下载 Word。
- 业务类型：招聘服务、劳务派遣、人力资源外包、其他或混合类型。先识别实际采购类型，再调整输出结构，不能把所有项目套成同一种服务。

参考材料为当前目录的《中指AI物业招投标Agent--产品介绍及操作指引.pdf》，重点参考第 38、39 页。借鉴其左侧原文、右侧结果、三个结果标签页和条款来源呈现方式；不复制品牌标识、宣传数据或未经验证的效果承诺。

## 3. 范围与边界

### 3.1 本期必须实现

| 功能 | 交付要求 |
| --- | --- |
| PDF 上传 | 单任务一份 PDF；文件校验；显示文件名、页数及处理状态 |
| PDF 处理 | 处理文字型、扫描型、图文混合型 PDF；提取正文、关键表格和可见图片文字 |
| AI 分析 | 真实调用 DeepSeek；输出指标需求、评分要求、废标红线 |
| 原文追溯 | 结果附原文摘录和 PDF 页码；点击来源跳转到原文页 |
| 结果确认 | 可编辑分析结果；保存修改后用于生成 |
| 企业资料 | 录入或选择本地示例资料，区分真实资料与示例资料 |
| 初稿生成 | 一键生成目录及主要章节；展示真实阶段状态 |
| 编辑与导出 | 编辑正文、单章重新生成、导出可编辑 Word |
| 任务恢复 | 查看历史结果；失败重试；取消任务；重启后保留已完成结果 |
| Key 安全 | Key 仅在后端配置；网页只显示是否已配置，不提供查看 Key 的入口 |

### 3.2 本期不包含

全网标讯采集、订阅推送、多用户协作、企业权限体系、企业知识库检索、资格真实性认证、完整报价测算、电子签章、自动递交投标、生产环境部署。

生成结果定位为“投标初稿”，不承诺可直接用于正式投标。识别出的红线表示招标文件存在相关要求，不代表已核验企业满足条件。

## 4. 完整使用流程

1. 启动本地服务，在浏览器打开工作台。系统检查模型配置和 OCR 可用状态。
2. 上传招标 PDF，查看文件概况和原文预览。
3. 首次提交云端分析前，确认本次将相关内容发送至 DeepSeek。该确认覆盖同一任务的分析与生成；更换文件或企业资料用途发生变化时重新提示。
4. 执行文字提取、按需 OCR、分段分析与结果核验。
5. 在三个标签页查看结果，点击来源核对原文；编辑错误或不完整的结果。
6. 确认或补充企业资料。缺失资料可以保留为待补事项，不阻断演示。
7. 点击“生成投标初稿”。自动生成目录及主要章节，不要求用户逐章点击。
8. 预览、编辑，必要时重新生成指定章节，最后导出 Word。

关键评分表或资格条款无法读取时，不显示“完整解析成功”。先展示已提取结果及缺失位置，由用户选择继续生成或更换文件。继续生成的初稿须保留未核对事项。

## 5. 页面与交互

### 5.1 工作台

- 顶部：产品名称、当前任务、模型配置状态及三个流程步骤。
- 左侧：PDF 预览，具备页码输入、翻页和缩放；文件名过长时省略并可查看全名。
- 右侧：解析结果或生成正文。宽屏下左右比例约为 45:55，可调整。
- 结果区：固定三个标签页“指标需求”“评分要求”“废标红线”。
- 来源按钮：如“PDF 第 12 页”，点击后左侧跳页；有可靠位置数据时可高亮，否则只跳页。
- 操作入口：上传或替换文件、开始解析、保存修改、生成初稿、导出 Word、取消任务。
- 历史任务：通过侧栏或抽屉打开，显示文件名、创建时间、状态，避免占用原文阅读区域。

采用克制的企业工作台风格，以清晰表格和条款为主。参考文档的蓝色导航可作为方向，但不照搬截图。状态、风险不能只靠颜色区分。窄屏改为原文/结果切换，保证表格可横向滚动，避免文字重叠。

### 5.2 任务状态

页面显示实际阶段，例如“正在识别第 8/25 页”“已分析 3/8 个片段”“已生成 2/7 章”。无法估计总耗时时使用阶段提示，不显示虚构倒计时或百分比。

需要覆盖：待上传、提取中、OCR 中、等待模型、分析中、完成、完成但有待核对项、生成中、失败、已取消、因服务重启而中断。

## 6. 三类解析结果

### 6.1 指标需求

| 分组 | 提取内容 |
| --- | --- |
| 项目概况 | 名称、采购单位、采购类型、地点、期限、预算及限价 |
| 服务范围 | 招聘交付、派遣或外包服务范围、边界、交付成果 |
| 人员要求 | 岗位、人数、资格、经验、到岗时限、替补要求 |
| 服务指标 | 响应时效、到岗率、招聘完成率、考核与验收标准 |
| 商务条件 | 付款、保证金、违约责任、结算及调价条件 |
| 准入要求 | 企业资格、许可证、业绩、联合体或分包限制 |
| 响应材料 | 必交文件、证明材料、提交格式和相关截止时间 |

字段必须区分“原文明确”“未明确”“存在冲突”“待核对”。未提到某项不等于没有该要求；无结果时不能自行填充行业常见标准。

### 6.2 评分要求

每项包括评分大类、评分项名称、分值或权重、得分条件、所需证明材料、来源、建议响应章节。价格评分公式同时保留原文，不能仅用模型改写后的公式替代。

支持表格、分档评分、多个包件。总分核对只在评分范围完整、计分关系明确时执行，不强行假设满分为 100 分。模型生成的响应建议与招标原文要求分栏展示。

### 6.3 废标红线

每条包括分类、触发条件、后果、原文摘录及来源。分类固定为：

- 明确无效投标条件：原文明确规定废标、无效、拒绝、否决等后果。
- 实质性响应要求：属于硬性要求，但当前证据未明确无效投标后果。
- 待人工确认风险：存在矛盾、表述不清或识别质量不足。

普通扣分项归入评分要求；需要交叉提示时可链接引用，不能升级为明确废标条件。演示版不根据企业资料自动给出“已合规”结论。

## 7. 投标初稿生成

### 7.1 输入与输出

输入为已保存的解析结果、相关原文片段、企业资料及用户选定的业务类型。生成前锁定输入版本，避免一边修改一边生成导致内容不一致。

默认生成约 6—8 个关键章节，正文目标约 4,000—7,000 个中文字；页数受表格及排版影响，不作为硬性指标。优先覆盖主要评分项与服务要求，不追求堆砌篇幅。

建议章节：项目理解、服务实施、人员与项目组织、适用的人事管理流程、质量考核、应急预案、评分响应表、证明材料及待补事项。实际目录按采购类型和招标要求调整。

### 7.2 内容约束

- 缺失的企业名称、资质、案例、履历、报价或承诺数值使用“【待补充：字段名称】”。
- 示例资料必须显式标记，导出的文件仍提示含示例信息。
- 招标文件要求与拟采用的实施建议分开表述，不能把建议写成企业既有事实。
- 人数、金额、服务期限和核心考核指标须与已确认要求核对。
- 输出评分项与章节对应关系；未覆盖内容列为待补，不宣称自动确保全部得分。

### 7.3 编辑与版本

分析结果修改后保留来源和原始提取值，并标记用户修改。修改来源摘录后，其引用验证状态重新计算。

重新生成章节前提示覆盖当前章节，保留上一版本以便恢复。企业资料或解析结果变更后，旧初稿显示“输入已更新”，不自动覆盖人工编辑内容。

Word 至少包含封面、章节标题、正文、必要表格和待补事项清单。生成可编辑文本，使用固定基础版式；自动分页目录、严格招标排版及暗标脱敏不在本期承诺范围。

## 8. 文件与异常处理

- 默认限制：单份 PDF 不超过 50 MB、150 页，作为后端可配置限制；上传前后均校验。
- 加密、损坏、无有效页面或不支持的文件明确拒绝，不进入付费模型调用。
- 支持扫描型及混合型文档，但低质量识别结果标记待核对；不得悄悄跳过识别失败页。
- 截图未显示的滚动区域、被裁掉的内容无法恢复；不可推断补齐。
- Key 缺失、认证失败、限流、余额或配额问题、网络超时分别提示处理方式，不展示凭据或原始请求头。
- 允许取消任务。取消会停止后续处理，但已经发出的模型请求可能仍产生费用。
- 失败后保留已完成阶段；重试默认使用有效检查点，重新分析须显式触发。

## 9. 数据与凭据安全要求

API Key 由演示人员在后端环境变量或本地 `.env` 中配置，不在网页输入、展示、下载或存储。模型状态只返回“已配置/未配置”和连接结果，不能返回 Key 前缀、后缀或其他片段。

网页默认仅通过 `127.0.0.1` 访问，不提供局域网共享开关。上传文件、企业资料、分析结果及导出文件保存在本机，默认不上传其他服务，不启用遥测。需要调用 DeepSeek 的数据范围在开始时说明。

演示使用已获授权的文件和资料。历史任务支持删除；删除前确认目标，删除范围包含该任务的文件、结果和导出物。系统明确说明本地删除不会撤回已发送至模型服务的数据。

## 10. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 文字型 PDF | 新文件触发真实 DeepSeek 调用，三类结果可查看、编辑和保存 |
| 扫描件 | 完成本地 OCR 后进入同一分析流程，保留识别来源标记 |
| 混合型 PDF | 正文有文字层时仍能识别有内容的截图，截图关键表格和条款不会因已有文字而跳过 |
| 原文追溯 | 标注为已验证的引用能匹配提取文本；页码跳转正确；失败引用不伪装为已验证 |
| 关键规则 | 在人工标注的演示样本上，所有明确无效投标条件被列出，普通扣分项不错误标为明确废标 |
| 评分与指标 | 演示样本的主要评分项、分值、岗位人数、期限及预算与人工基准一致；不明确处有提示 |
| 初稿 | 一次点击完成主要章节，评分项有对应章节或待补状态，无编造企业事实 |
| 导出 | Word 可打开和编辑，保留修改内容、必要表格、示例标记和待补事项 |
| 安全 | 浏览器资源、接口响应、日志和导出物中不存在测试用 Key；外部网页不能触发付费调用 |
| 异常 | 模型失败可解释、可重试；取消有效；服务重启后历史结果可查看 |

验收使用至少三类样本：文字型、扫描型、图文混合型。业务正确性应以获授权的人力资源招标文件建立人工基准，参考 PDF 仅用于验证布局与截图识别，不能代替业务样本。

## 11. 开发顺序与待确认输入

1. 搭建本地服务、Key 配置、文件上传、PDF 预览和任务存储。
2. 完成三种 PDF 路径、真实 DeepSeek 分析、证据引用与结果编辑。
3. 完成企业资料、初稿生成、单章修改和 Word 导出。
4. 使用真实样本校准解析，完成安全检查、异常测试和演示走查。

开发前需要提供：DeepSeek API Key（仅写入本机配置）、可用模型 ID、2—3 份代表性招标样本、演示企业资料。没有客户资料时可先用明确标注的示例资料开发，不能以此宣称已通过客户业务验收。

基础 Demo 预计 3—5 个工作日；如果样本包含复杂扫描表格或需要处理较多 OCR 兼容问题，预留 5—8 个工作日。实际处理耗时和模型成本通过样本测量后记录，不承诺固定生成时长。
